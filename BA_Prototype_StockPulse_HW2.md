# StockPulse MOEX — прототип продукта

**My First Data Project — домашнее задание №2**  
**Дата:** 19.11.2026

## 1. Ключевая гипотеза

**StockPulse MOEX** — сервис для быстрой проверки новостного фона перед сделкой с акциями. Пользователь уже провёл собственный анализ и хочет убедиться, что не пропустил важное событие. Сервис выделяет потенциально значимые новости, кратко поясняет их связь с компанией и даёт ссылку на источник. Это не рекомендация покупать или продавать.

**Основная гипотеза:** если предложить частным инвесторам, самостоятельно анализирующим российские акции, такую проверку перед покупкой SBER, то в первый месяц пилота **не менее 60% полученных оценок будут «полезно» или «частично полезно», а не менее 60% ответивших сообщат, что учли информацию в своём анализе, дополнительно её проверили или пересмотрели первоначальную оценку**. Предполагаем, что краткие предупреждения помогают не упустить существенные новости без просмотра всей ленты.

**Сегмент:** частные инвесторы, самостоятельно принимающие решения по российским акциям.  
**Сценарий:** проверка новостей по SBER непосредственно перед предполагаемой покупкой.  
**Монетизация:** ежемесячная подписка на расширенный мониторинг нескольких компаний. Готовность платить пока не проверена.

Дополнительная гипотеза: предупреждения вызывают интерес к первоисточникам — не менее **30% просмотров предупреждений** заканчиваются переходом по ссылке на новость.

Все численные пороги выбраны предварительно для учебного прототипа, а не получены из исследований.

## 2. Метрики и способ проверки

| Метрика | Цель / критерий | Сравнение или baseline | Как измеряем |
|---|---|---|---|
| Полезность информации | **≥ 60%** ответов «полезна» или «частично полезна» | Данных пока нет, первый пилот станет точкой отсчёта | Короткий вопрос после просмотра предупреждения |
| Использование информации | **≥ 60%** ответивших учли её, дополнительно проверили или пересмотрели оценку | Данных пока нет, первый пилот станет точкой отсчёта | Второй вопрос после просмотра |
| Переходы к источнику | **≥ 30%** просмотров предупреждений с переходом | Исходный показатель первого пилота, затем сравнение версий | Счётчик открытий карточек и переходов |
| **Противовесная:** нерелевантные предупреждения | **≤ 40%** оценённых предупреждений признаны нерелевантными | Исходный уровень первого пилота | Отдельная отметка «не относится к акции или ситуации» |
| **Противовесная:** лишние действия | Отслеживать, не усложняет ли сервис проверку | Предыдущая версия прототипа | Время в приложении, незавершённые проверки, комментарии |
| Качество отбора новостей (ML) | Precision выше простого поиска по ключевым словам | Фильтр по названию компании и тикеру | Ручная разметка контрольной выборки, оценка после каждой версии модели |

**Вопросы пользователю:**
1. «Была ли информация полезна для вашего анализа?» — да / частично / нет.
2. «Как вы использовали информацию?» — учёл при оценке / дополнительно проверил / пересмотрел оценку / не использовал.
3. «Относится ли предупреждение к выбранной акции или ситуации?» — да / нет.

Дополнительно фиксируем запуск проверки, просмотр карточки, переход к новости и длительность сессии. Долгое пребывание в приложении само по себе не считаем успехом: цель — помочь быстро получить нужную информацию.

Показатели считаем по мере использования прототипа; для предварительного вывода возьмём ориентир в **20 полученных анкет**, без отдельного набора участников к сдаче ДЗ. Если реальных ответов пока нет, гипотезы считаются **непроверенными**, а тестовые действия нужны только для проверки работы счётчиков. Метрики пересматриваем после первого пилота.

## 3. Что войдёт в прототип

**Делаем:** простую веб-страницу на Streamlit для SBER. На ней будут результаты проверки новостного фона, краткие карточки потенциально значимых событий, их дата, источник, объяснение возможной значимости, ссылка на публикацию и форма обратной связи. Добавим запись основных действий пользователя.

**Пока не делаем:** браузерное расширение, уведомления, другие акции, личные кабинеты, оплату, автоматическую торговлю и полноценный прогноз «рост / боковик / снижение». Это возможные следующие этапы, но они не нужны для проверки полезности предупреждений.

## 4. Готовые инструменты и собственная работа

**Берём готовое:** исторические новости из RussianFinancialNews, котировки SBER через `moexalgo`, `pandas` для обработки данных, `scikit-learn` для первого ML-эксперимента и Streamlit для интерфейса. Для хранения событий и отзывов на первом этапе подойдёт SQLite.

**Делаем сами:** отбор новостей по SBER, проверку их релевантности, простое ранжирование потенциально значимых событий, карточки предупреждений, сбор обратной связи и сравнение ML-отбора с поиском по ключевым словам. Это основная логика продукта — от её качества зависит, будет ли предупреждение полезным или создаст информационный шум.

У нас уже есть 91 955 финансовых публикаций и 744 дневные свечи SBER за 2022–2024 годы. Найденные новости по SBER пока являются кандидатами: их релевантность ещё нужно проверить. Связь новостей с изменениями котировок будем изучать отдельно, без обещания, что конкретная публикация вызвала движение цены.

## 5. Главный риск и формат прототипа

**Главный риск:** пользователь получает много нерелевантных предупреждений или не видит в них пользы для своего анализа. Поэтому проверяем не только просмотры и переходы, но и оценки полезности, фактическое использование информации и долю нерелевантных сообщений.

**Формат:** веб-прототип на Streamlit. Сначала можно использовать заранее подготовленные исторические карточки и проверить интерфейс и сбор событий. После проверки отбора новостей подключим результаты модели. В дальнейшем возможен браузерный плагин, который показывает такую проверку рядом со страницей акции.

## 6. Когда завершаем проверку

Первый пилот завершаем после накопления достаточной обратной связи (ориентир — 20 заполненных форм) или по окончании первого месяца, если ответов мало. Во втором случае не делаем вывод о подтверждении гипотез.

- **Гипотеза полезности проходит предварительную проверку**, если достигнуты оба порога: **≥ 60%** полезных/частично полезных оценок и **≥ 60%** ответов об использовании информации.
- **Противовесный критерий:** **≤ 40%** оценённых предупреждений признаны нерелевантными. Если порог превышен, дорабатываем отбор новостей, даже если основные показатели хорошие.
- **Гипотеза интереса к источникам:** ориентир **≥ 30%** переходов; если ниже, отдельно разбираем причины — пользователю могла быть достаточна сводка.
- **ML-проверка:** сравниваем релевантность отобранных новостей с простым поиском по ключевым словам. Если улучшения нет, не называем отбор более качественным и пересматриваем подход.

Пороговые значения — критерии решения для первой версии, а не доказательство предотвращённых финансовых потерь. Реальную эффективность можно оценивать только после появления пользовательских данных.
