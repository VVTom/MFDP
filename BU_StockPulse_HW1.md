# StockPulse MOEX — бизнес-анализ

**My First Data Project — домашнее задание №1**

## 1. Бизнес-анализ (Business Understanding)

Перед покупкой акций человек обычно изучает графики, отчёты и новости. Но какую-то важную публикацию легко пропустить, особенно если приходится проверять несколько сайтов. Даже найденную новость не всегда просто оценить с точки зрения возможных последствий для акции.

Хочу сделать **StockPulse MOEX** — небольшой сервис для проверки новостного фона перед сделкой. Пользователь выбирает акцию и получает подборку событий, на которые стоит обратить внимание: краткое описание, возможную связь с компанией и ссылку на источник. Это дополнительная информация для собственного анализа, а не совет покупать или продавать.

**Пользователи** — частные инвесторы, которые самостоятельно принимают решения по российским акциям. Внешнего заказчика и отдельной команды нет, проект учебный. При необходимости могу обращаться за помощью к преподавателям курса.

**Цель проекта** — помочь пользователю быстрее находить потенциально важные новости и не упускать их при принятии решения. Насколько это окажется полезным, ещё нужно проверить.

Новости и котировки уже есть на РБК Инвестициях, Финаме и в брокерских приложениях. В StockPulse хочу сделать акцент на короткой проверке перед сделкой: не просто показать ленту, а выделить события, которые могут заслуживать дополнительного внимания.

В первой версии ограничусь **SBER** и простым веб-интерфейсом на Streamlit: предупреждения, краткие карточки новостей, ссылки на источники и обратная связь. Другие акции и расширение для браузера оставлю на потом.

## 1.1. Текущая ситуация (Assessing current solution)

Для работы достаточно моего компьютера и Python. Планирую использовать `pandas`, `scikit-learn` и библиотеки для обработки текста. Дополнительное оборудование не требуется.

Данные уже частично проверены:

- **Новости:** датасет [RussianFinancialNews](https://huggingface.co/datasets/Kasymkhan/RussianFinancialNews) — 91 955 публикаций. За 2022–2024 годы автоматическим поиском найдено 3 016 новостей-кандидатов по SBER, 5 293 по GAZP и 2 299 по LKOH. Это ещё не означает, что все они действительно подходят.
- **Котировки:** через [`moexalgo`](https://moexalgo.github.io/) получены 744 дневные свечи SBER за 03.01.2022–30.12.2024. В загруженных полях пропусков нет, даты не повторяются. Полноту данных по торговым дням нужно проверить отдельно.
- **Хранение:** пока файлы CSV/Parquet на компьютере, код — на GitHub. Для сохранения действий и отзывов пользователей можно использовать SQLite. Перед публикацией исходных данных нужно проверить условия их использования.

**Возможные риски:**

| Риск | Что буду делать |
|---|---|
| У части новостей нет точного времени публикации или заголовка | Проверю записи и буду осторожно учитывать время появления новости |
| В подборку попадают новости не по теме, а важные события могут пропускаться | Размечу часть новостей вручную и проверю ошибки отбора |
| Новостей за нужный период недостаточно или их качество низкое | Начну с проверенного периода 2022–2024 годов; при необходимости поищу другие источники |
| Связь новостей с движением цены окажется слабой | Сравню модели с новостями и без них, не буду заранее обещать улучшение |
| Не хватит времени на все функции | Сначала сделаю рабочую версию только для SBER |

## 1.2. Решаемые задачи с точки зрения аналитики (Data Mining goals)

**Основная ML-задача** — отбирать новости, которые относятся к SBER или важным для него событиям, и пытаться выделять среди них наиболее значимые. Начну с простой классификации публикаций на релевантные и нерелевантные. Для проверки вручную размечу часть новостей.

**Признаки для отбора новостей:** текст и заголовок, упоминания компании, тема и тональность публикации. Сначала сделаю простой поиск по названию компании и тикеру — это будет **baseline**. Затем сравню его с моделью, работающей с текстом.

**Метрики отбора:** `precision`, `recall` и `F1-score`. Важно не только показывать подходящие новости, но и не пропускать действительно значимые публикации. Успехом буду считать улучшение качества относительно поиска по ключевым словам на одной и той же вручную размеченной выборке.

**Дополнительная исследовательская задача** — проверить, связаны ли характеристики новостей с последующим движением цены. Для этого можно взять изменения цены, объём торгов и волатильность, добавить количество, темы и тональность новостей за предыдущий период. Попробую разделить движение SBER за следующие три торговых дня на три класса: рост, боковик и снижение. Границы классов определю по обучающим данным.

Здесь сравню простую модель по котировкам с моделью, в которую добавлены новостные признаки. **Основная метрика — `macro-F1`, дополнительная — `balanced accuracy`**. Проверять качество буду на более позднем периоде, который не использовался при обучении. Успехом будет улучшение относительно модели без новостей; если его не окажется, это тоже важный результат. При этом изменение цены после публикации не доказывает, что именно новость стала его причиной.

**Результат для пользователя:** подборка потенциально значимых новостей по SBER с кратким пояснением и первоисточником. Исследование котировок поможет понять, можно ли в дальнейшем добавить более обоснованную оценку важности событий. Полноценный прогноз «рост / боковик / снижение» в первую версию интерфейса не включаю.

## 1.3. План проекта (Project Plan)

| Этап | Что планирую сделать |
|---|---|
| **1. Business Understanding** | Определить проблему, пользователей, цель проекта и основные риски |
| **2. Data Understanding** | Изучить новости и котировки, проверить качество данных и количество подходящих публикаций |
| **3. Data Preparation** | Очистить данные, убрать дубли, разметить часть новостей и подготовить признаки |
| **4. Modeling** | Сделать отбор по ключевым словам и модель для работы с текстом; по возможности сравнить модели движения цены с новостями и без них |
| **5. Evaluation** | Сравнить метрики с baseline, изучить ошибки и проверить, какие результаты можно использовать в сервисе |
| **6. Deployment** | Собрать веб-прототип на Streamlit с предупреждениями, ссылками и обратной связью; подготовить демонстрацию |

Сначала сосредоточусь на отборе новостей и простом прототипе. Если останется время, расширю список компаний и подробнее исследую связь новостей с движением котировок.
